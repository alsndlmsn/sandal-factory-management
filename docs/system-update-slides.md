# نظام مصنع الصندل — ملخص التحديثات والطباعة والإرشاد

## توجيه العرض
- اللغة: العربية.
- الاتجاه: RTL.
- النمط: مهني حديث، ألوان النظام teal/navy/mint، نصوص قصيرة، أرقام كبيرة، جداول ومخططات بسيطة.
- الجمهور: المدير وفريق التشغيل.
- عدد الشرائح: 8.
- مصدر الأرقام: أدلة الاختبار الداخلية بتاريخ 25 أغسطس 2026؛ لا تعرض الشريحة أرقامًا تقديرية على أنها أداء ضغط.

---

## الشريحة 1 — الغلاف
العنوان: «نظام مصنع الصندل»
العنوان الفرعي: «ملخص التحديثات والطباعة ونتائج الاختبار النهائي»
نص قصير: «نسخة عربية RTL لإدارة المبيعات والمخزون والإنتاج والموظفين والمالية».
عنصر بصري: علامة SP هندسية بسيطة مستوحاة من هوية النظام، بلا استخدام شعار حقيقي غير مقدم.

## الشريحة 2 — ماذا تغير؟
العنوان: «من نظام يعمل إلى نظام يشرح نفسه»
اعرض أربع بطاقات:
1. إرشاد داخل التطبيق: مساعدة سياقية وجولات قابلة للتخطي.
2. تقارير قابلة للطباعة: صفحة أو تقرير أو قسم.
3. تجربة هاتف وكمبيوتر: RTL، مسافات واضحة، وأزرار مناسبة.
4. أمان وترابط: الحفاظ على RLS والصلاحيات وسجل التدقيق.
نص ختامي: «التحديثات أضيفت كطبقات مستقلة دون إعادة كتابة منطق العمليات.»

## الشريحة 3 — مؤشرات البيانات الحية
العنوان: «حجم الاختبار والبيانات المترابطة»
اعرض أرقامًا كبيرة: 90 عاملًا، 101 فاتورة بيع معتمدة، 30 شراءً معتمدًا قبل إضافة شراء الاختبار، 132 حركة مخزون، 126 قيدًا، 616 سجل تدقيق قبل الجولة.
اعرض مخطط أعمدة للمقارنة: فواتير البيع 90 قبل الجولة مقابل 101 بعدها.
تعليق: «تمت إضافة 11 فاتورة، أي زيادة 12.22% مقارنة بخط الأساس، دون حذف البيانات الموجودة.»

## الشريحة 4 — دورة العمليات المختبرة
العنوان: «اختبار الترابط من الحركة إلى القيد»
اعرض مسارًا أفقيًا أو حلقيًا:
مبيعات → دفع كاش/بنك → مخزون → خزنة أو بنك → قيد يومية → سجل تدقيق → تقرير.
اعرض بجانب المسار سيناريوهات: 10 فواتير اختبار، 5 كاش + 5 بنك، دفعة لاحقة واحدة، مرتجع واحد، مصروف واحد، شراء واحد، حركة مخزون واحدة، إنتاج واحد، فترة مرتب واحدة، سلفة واحدة، حافز واحد.
نص مهم: «أخطاء الاتزان = صفر، والسجلات اليتيمة = صفر بعد الإصلاح وإعادة الاختبار.»

## الشريحة 5 — نظام التقارير والطباعة
العنوان: «طباعة كل ما يحتاجه المصنع»
اعرض جدولًا مختصرًا:
| النوع | الوظيفة |
| طباعة الصفحة | إخراج الصفحة الداخلية كاملة |
| طباعة التقرير | التقارير التشغيلية والقوائم المالية واليومية والتدقيق والتسوية البنكية |
| طباعة القسم | إخراج لوحة أو جدول أو مؤشرات منفردة |
| الطباعة المتخصصة | فاتورة تفصيلية وقيد يومية تفصيلي |
خصائص التصميم: A4، هوية المصنع، رقم المصنع، العنوان والتواصل، التاريخ والمستخدم، إزالة الأزرار والبحث، جداول RTL قابلة للقراءة.

## الشريحة 6 — الإرشاد والتعلم داخل النظام
العنوان: «المستخدم لا يحتاج إلى حفظ الخطوات»
اعرض خمس وظائف: مركز مساعدة دائم، «كيف أستخدم هذه الصفحة؟»، «أرني كيف» بجولة فعلية، «ما هذا؟» للحقول والأزرار، بحث في الصفحات والأخطاء.
اعرض نتائج الاختبار: 20 صفحة أنتجت HTML بلا استثناءات، 7 نتائج للبحث عن «فاتورة»، نجاح التفضيلات، نجاح الجولة، نجاح وضع «ما هذا؟».
تعليق أمان: «لا يظهر الإرشاد قبل المصادقة، ولا يضيف أي صلاحية جديدة.»

## الشريحة 7 — تخصيص الشعار وهوية الطباعة
العنوان: «كيف أضع شعار المصنع؟»
اعرض خطوات مرقمة:
1. جهّز PNG أو SVG بخلفية شفافة.
2. ضعه في `assets/factory-logo.png`.
3. عدّل `factoryLogo:'./assets/factory-logo.png'` في `js/config.js`.
4. ارفع الملف وبدّل إصدار الكاش عند الحاجة.
5. اختبر فاتورة وتقريرًا؛ عند غياب الشعار تظهر علامة SP البديلة.
ملاحظة: «لم يوضع شعار تجريبي؛ أرسل الشعار المعتمد ليتم دمجه بصريًا.»

## الشريحة 8 — الجودة والخطوات التالية
العنوان: «النتيجة والحدود بوضوح»
اعرض لوحة حالة: syntax checks ناجحة، diff check ناجح، secret scan نظيف، GitHub Pages build ناجح، إصلاح دفعة لاحقة في migration 047، إغلاق امتيازات anon في migration 048.
اعرض ثلاثة حدود: الاختبار الوظيفي ليس اختبار ضغط متزامنًا، ملاحظات Supabase الأمنية والأدائية تحتاج مراجعة، يجب إدخال بيانات المصنع الحقيقية ومراجعتها محاسبيًا.
الخاتمة: «النظام مناسب للتجربة الداخلية والتشغيل التجريبي المنظم، مع اختبار قبول لكل دور ونسخ احتياطي قبل الاعتماد الكامل.»
