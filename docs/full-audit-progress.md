# تقرير التدقيق والاختبار النهائي

## مصنع الصندل للأوعية البلاستيكية

**الإصدار:** `rebuild-v2` — **التاريخ:** 24 أغسطس 2026 — **إعداد:** Manus AI

## 1. نطاق العمل

أُجري تدقيق تشغيلي متكامل للنسخة العربية ذات الاتجاه من اليمين إلى اليسار، المبنية باستخدام HTML وCSS وJavaScript وSupabase، مع الحفاظ على نشر الواجهة كأصول ثابتة عبر GitHub Pages. شمل التدقيق الواجهة، مسارات الصلاحيات، الترابط بين العمليات التشغيلية والمالية، القيود المحاسبية، الاستجابة للشاشات، تنظيف بيانات الاختبار، وفحص مستشار أمان Supabase.

لم تكن هناك بيانات تشغيل حقيقية قبل بدء الاختبار. أُنشئت بيانات مؤقتة موسومة بعبارة «اختبار مؤقت» بموافقة المستخدم، ثم أُعيد ضبط المصنع بعد انتهاء الاختبارات مع الحفاظ على المستخدمين والأدوار والصلاحيات والإعدادات والحسابات المحاسبية.

## 4. الأعطال التي ظهرت أثناء الاختبار والإصلاحات

ظهر في مسار البيع تعارض في اسم `total` بين متغير الدالة وعمود جدول المبيعات؛ عولج في migration 038 بتأهيل الحقول. ثم ظهر تحديث غير مسموح للعمود المولّد `remaining_amount`؛ عولج في migration 039 باستبعاده من التحديث وترك حسابه للقاعدة.

في مسار المرتجعات أرسل التطبيق المعامل `p_notes` إلى دالة لا تدعمه، فأزيل المعامل من الاستدعاء. أثناء الاعتماد ظهر تعارض في الاسم `si.id` بسبب تعارض alias مع متغير PL/pgSQL، كما كان تحديث `sales.remaining_amount` غير مناسب لأنه عمود مولّد؛ عولج المساران في migration 040.

في اعتماد كشف المرتبات ظهر تعارض اسم `incentives` بين متغير PL/pgSQL وعمود السجل، فأعيدت كتابة مشغل قيد الاستحقاق باستخدام متغير مؤهل وalias صريح في migration 041. بعد ذلك نجح اعتماد الفترة، وخصمت السلفة وسجل القيد.

جميع ملفات JavaScript المعدلة اجتازت `node --check`، كما اجتاز المشروع `git diff --check` دون مخرجات خطأ.

## 5. الصلاحيات والأمان

| الفحص | النتيجة |
| --- | --- |
| أدوار المستخدمين | المدير ظهر «مدير»، وحساب محمد حسن ظهر «حسابات». |
| صلاحيات الحسابات | شملت لوحة التحكم والموظفين والحضور والمصروفات والخزائن والبنوك والمرتبات والتقارير واليومية والتسوية، ولم تشمل المستخدمين والمنتجات والمبيعات والمخزون والإنتاج والمرتجعات. |
| الجداول الحساسة | تم تفعيل RLS على `role_controls` و`finance_transfers` و`cash_counts` و`return_refunds`. |
| تنفيذ الدوال من anon | صفر دوال SECURITY DEFINER قابلة للتنفيذ من `anon`. |
| مستشار Supabase | 0 أخطاء و64 تحذيرًا. التحذيرات من نوع أن دوال `SECURITY DEFINER` قابلة للتنفيذ من دور `authenticated`؛ وهي دوال RPC تشغيلية محمية بفحوص الصلاحيات داخلها، لكن التحذير لا يُعد منتهيًا ولا يجوز ادعاء انعدام كل المخاطر. |
| الاستجابة | اتجاه الصفحة RTL، و`scrollWidth` مساوي لعرض نافذة الفحص دون تجاوز أفقي. قواعد CSS تتضمن قائمة جانبية منزلقة للهاتف، جداول قابلة للتمرير، بطاقات تدقيق متجاوبة، ونقاط توقف عند 780 و430 بكسل. |

لم يُنفذ تسجيل دخول مستقل بحساب الحسابات أثناء الاختبار حتى لا تُطلب أو تُعاد طباعة كلمة مرور؛ عُوّض ذلك بفحص SQL للأدوار والصلاحيات، مع بقاء جلسة الاختبار في المتصفح جلسة المدير فقط.

## 6. تنظيف بيانات الاختبار

استُخدمت دالة `reset_factory_data('إعادة ضبط المصنع')` من جلسة المدير المصادق عليها. قبل التنفيذ جرى فحص تعريف الدالة والتأكد من أنها تنظف الجداول التشغيلية والحركات والقيود والموظفين والمنتجات والحسابات النقدية والبنكية، مع الحفاظ على profiles والأدوار والصلاحيات والإعدادات والحسابات المحاسبية.

أظهر التحقق بعد التنظيف أن `profiles = 2` و`user_roles = 2` و`roles = 5`. عادت جميع الجداول التشغيلية التي استُخدمت في الاختبار إلى صفر، بما في ذلك المنتجات والمخازن والبنوك والخزائن والمشتريات والإنتاج والمبيعات والمرتجعات والموظفين والحضور والسلف والحوافز والمرتبات والمصروفات والحركات النقدية والبنكية والتحويلات وكشوف البنك وقيود اليومية. بقي سجل تدقيق واحد خاص بعملية إعادة الضبط نفسها، بينما كان عدد السجلات التي تحتوي على علامة «اختبار مؤقت» صفرًا.

> **حالة البيانات عند التسليم:** لا توجد بيانات اختبار تشغيلية متبقية. المستخدمون والأدوار والصلاحيات محفوظة.

## 8. الخلاصة وحدود الجاهزية

النسخة الحالية مترابطة وظيفيًا في المسارات التي اختُبرت، وتعرض الأدوار الصحيحة، وتنفذ العمليات المؤقتة عبر RPC محمية، وتعيد أثر الاختبار إلى حالة تشغيل نظيفة. تم إصلاح أربعة أعطال توافقية ظهرت فقط عند تمرير عمليات حقيقية من الواجهة إلى مخطط Supabase، وهي موثقة في migrations 038–041.

مع ذلك، لا تُعد النتيجة شهادة أمان مستقلة أو اعتمادًا محاسبيًا قانونيًا. ما زالت نتيجة مستشار Supabase تحتوي على 64 تحذيرًا مرتبطًا بإتاحة دوال `SECURITY DEFINER` للمستخدم المصادق عليه. يلزم في مرحلة أمنية لاحقة مراجعة كل RPC وتقليل المنح على مستوى الدوال أو نقل الدوال غير اللازمة من schema المعروض، مع اختبار منفصل لكل دور فعلي قبل تشغيل معاملات حقيقية واسعة.
