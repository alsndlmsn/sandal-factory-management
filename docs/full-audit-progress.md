# سجل المراجعة الشاملة

التاريخ: 2026-08-24

## النطاق والحدود

المراجعة الحالية تشمل النسخة المحلية المصادق عليها، والنسخة العامة، وقراءة بنية Supabase والصلاحيات. لا تُنشأ ولا تُعدّل أي بيانات تشغيلية حقيقية أو وهمية، ولا تُنفذ عمليات اعتماد أو دفع أو حذف.

## حالة النشر والملفات

المستودع على الفرع `rebuild-v2` نظيف عند بدء المراجعة، والفرعان `main` و`rebuild-v2` يشيران إلى `557b4ec`. حالة GitHub Pages كانت `built`، والعنوان العام يظهر «مصنع الصندل للأوعية البلاستيكية»، وملفات JavaScript وCSS تصل إلى الموقع العام. فحوص صياغة `js/app.js` و`js/supabase.js` و`sw.js` و`git diff --check` نجحت، وفحص الأسرار لم يجد service role أو JWT داخل المنتج.

## اختبار المدير

ظهرت شاشة الدخول العربية، وتم الدخول بحساب المدير الموجود في جلسة الاختبار. بعد اكتمال التحقق ظهرت لوحة التحكم والقائمة الجانبية كاملة، مع زر «خروج»، وظهرت بطاقات الملخص وحالة الاتصال، دون شاشة خطأ أو تعليق. ما زال النظام بلا سجلات تشغيلية، لذلك القيم المالية والصنف والعمال تظهر صفرًا بشكل متوقع في بيئة الاختبار الفارغة.

## تنبيه Supabase الأمني

أظهر فحص Supabase الأمني أن أربع جداول في `public` لديها RLS معطل: `role_controls` و`finance_transfers` و`cash_counts` و`return_refunds`. كما أظهر أن سياسات موجودة لبعضها لكنها غير فعالة بسبب تعطيل RLS. هذا تنبيه أمني حرج يمنع إعلان الجاهزية الإنتاجية الكاملة حتى تُفعّل RLS وتُراجع السياسات المناسبة. لم يتم تطبيق SQL تلقائيًا لأن تفعيل RLS بلا سياسات صحيحة قد يمنع الوصول أو يسبب تعطل الوظائف؛ يلزم إصلاح مُراجع قبل التشغيل الفعلي.

وأظهر الفحص أيضًا تحذيرات بأن عددًا من دوال `SECURITY DEFINER` الحساسة قابلة للتنفيذ عبر دور `anon`، مثل إنشاء واعتماد المبيعات والمشتريات والمصروفات والتحويلات والإنتاج والمرتجعات والموظفين. يلزم تقييد `EXECUTE` للدور `authenticated`/الصلاحيات المناسبة قبل إعلان الأمان الكامل.

## نتائج لاحقة

سيُستكمل اختبار الأقسام والأزرار، وقراءة سياسات الأدوار، وتوثيق ما يعمل وما يمنع الجاهزية.

## الجولة الآلية للأقسام

تم الانتقال بالمسار إلى جميع الأقسام: لوحة التحكم، دليل التشغيل، المنتجات، المخزون، الإنتاج، المبيعات، المرتجعات، الموردون، الخزائن، المصروفات، الموظفون، الحضور، المرتبات، المستخدمون، الأدوار، التقارير، التدقيق، والإعدادات. كل قسم أعاد عنوانه الصحيح وخرج من حالة التحميل، ولم يظهر نص «تعذر تحميل القسم». ظهرت نماذج وأزرار الأقسام التي تتطلبها الواجهة، ولم تُنفذ أي عملية حفظ. لم تظهر أخطاء console بعد الجولة.

## اختبار صفحة الأدوار والصلاحيات

ظهرت خمسة أدوار في صفحة الصلاحيات: مدير، حسابات، مخزن وموردين، مبيعات، وإنتاج. عُرض لكل دور نطاق البيانات وبيان إظهار الحسابات المالية والصلاحيات المرتبطة. المدير ظهر بنطاق «كل البيانات» وإظهار الحسابات المالية، بينما الأدوار التشغيلية ظهرت بنطاق «بيانات القسم» وإظهار مالي غير مفعل. تم فتح نموذج تعديل ضوابط دور «حسابات» فظهرت خيارات النطاق، الوارد والصادر والتحويل والجرد والاعتماد وحدود المبالغ، ثم أُغلق النموذج دون حفظ. هذه نتيجة اختبار واجهة المدير، وليست إثباتًا كاملًا لحسابات مستخدمين فعلية لكل دور.

## اختبار الأزرار والنوافذ

تم فتح وإغلاق النماذج غير التغييرية للأقسام التالية: إضافة منتج؛ إنشاء مخزن وحركة مخزون؛ أمر إنتاج؛ فاتورة بيع؛ مرتجع؛ مورد ومادة خام وشراء؛ حركة مالية وتحويل وجرد؛ منصرف؛ موظف؛ كشف مرتب وسلفة؛ مستخدم؛ وتعديل ضوابط الدور. جميع الأزرار المستهدفة فتحت نافذة النموذج ثم أُغلقت دون بقاء طبقة فوق الصفحة، ولم تُنفذ أي عملية حفظ أو اعتماد أو دفع. لم تظهر أخطاء console بعد الجولة.

## اختبار إدارة المستخدمين

ظهرت قائمة المستخدمين وبها حساب المدير، وحقل البحث، وزر «إضافة مستخدم». نموذج الإضافة يطلب الاسم والبريد والدور وكلمة مرور مؤقتة، ثم أُغلق دون إنشاء حساب. لم تظهر في واجهة القائمة أزرار تعديل أو تعليق أو تفعيل أو إعادة تعيين كلمة المرور للمستخدم الحالي أو للمستخدمين الآخرين؛ لذلك هذه المتطلبات ليست مكتملة في الواجهة الحالية رغم أن بعض عمليات الإدارة مدعومة خلفيًا في Edge Function وفق الملفات.

## اختبار البحث

بعد إضافة معالج البحث الموحد، تم اختبار صفحة المستخدمين وكتابة «عصام» في حقل البحث؛ بقي صف المدير ظاهرًا مطابقًا للبحث. هذا يؤكد عمل معالج الحقول العامة على الأقل في صفحة المستخدمين، مع بقاء اختبار الصفوف متعددة السجلات مؤجلًا لعدم وجود بيانات تشغيلية وعدم إنشاء بيانات وهمية.

## اختبار الخروج

من صفحة المستخدمين تم الضغط على «خروج»، فعادت الشاشة فورًا إلى بوابة الدخول، واختفت القائمة والجلسة، ولم يظهر أي خطأ في console.

## اختبار النسخة العامة

عند فتح GitHub Pages دون جلسة مصادق عليها ظهر نموذج تسجيل الدخول فقط، ولم تظهر لوحة التحكم أو القائمة أو أي بيانات. لم يظهر console output في الفحص العام.

## ملخص تنبيهات الأمان

نتيجة فحص Supabase الأمني تحتوي على 6 أخطاء و77 تحذيرًا. الأخطاء تشمل الجداول الأربعة ذات RLS المعطل، مع تنبيه إضافي مرتبط بوجود سياسات غير فعالة؛ كما رصد الفحص 32 دالة `SECURITY DEFINER` حساسة قابلة للتنفيذ من دور `anon` وفق تقرير المستشار. لم تُطبّق أي معالجة تلقائية على قاعدة البيانات.
