# نظام إدارة مصنع الصندل للأوعية البلاستيكية

نظام ويب عربي متجاوب لإدارة المصنع من الهاتف والكمبيوتر. صُمم النظام بواجهة RTL واضحة، وبمكونات HTML5 وCSS3 وVanilla JavaScript، مع Supabase Auth وPostgreSQL وRPCs آمنة، ويُجهز للنشر على GitHub Pages.

## نطاق النظام

يوفر النظام لوحة مدير تلخص مبيعات اليوم والمصروفات والأصناف والعمال، مع دليل تشغيل يوضح ترتيب الإعداد. وتشمل الوحدات المنتجات، المخازن، حركات المخزون، الإنتاج، المبيعات ونقطة البيع، المرتجعات والتالف، الموردين والمشتريات والخامات، الخزائن والبنوك، المصروفات، الموظفين، الحضور والانصراف، المرتبات والسلف والحوافز، التقارير، المستخدمين، الأدوار والصلاحيات، سجل التدقيق والإعدادات.

## الترابط التشغيلي والمالي

يسجل المنتج مرة واحدة ويظهر في نقطة البيع والمخزون والإنتاج والتقارير. لا تُخصم كمية البيع ولا تُسجل الدفعة المالية إلا بعد اعتماد الفاتورة. الشراء المعتمد ينشئ حركة وارد للمخزون ويربط الدفع بحساب المورد والخزنة أو البنك. المرتجع يبدأ من الفاتورة الأصلية، ويُقسم إلى صالح وتالف وفحص، مع رد مالي من الحساب الذي استقبل الدفع. الإنتاج المعتمد يدخل الناتج المقبول إلى مخزن المنتجات الجاهزة ويسجل التالف. السلفة تخرج من الخزنة أو البنك وتظهر في كشف العامل، والحافز يدخل في حساب المرتب، ودفع المرتبات والمصروفات يسجل في الدفتر المالي.

> العمليات الحساسة، مثل الاعتماد والدفع والتسوية وتغيير الصلاحيات، لا تُنفذ كإجراء محلي صامت؛ بل تمر عبر Supabase RPC مع جلسة وصلاحية وقفل للسجل عند الحاجة.

## الأمان

المفتاح العام فقط موجود في الواجهة. لا يحتوي المستودع على service role key أو كلمة مرور. إنشاء المستخدم وتعديل دوره وكلمة المرور يتم عبر Edge Function إدارية تتحقق من جلسة المدير، ولا تُعرض كلمات المرور أو تُحفظ في قاعدة بيانات التطبيق. يحتفظ النظام بتاريخ العمليات ولا يحذف الموظف أو الفاتورة أو الحركة المعتمدة حذفًا مباشرًا، ويعرض سجل التدقيق المنفذ والوقت والقسم ورقم السجل والقيم السابقة والجديدة والسبب عند توفره.

## الأوفلاين

تخزن طبقة PWA الملفات الثابتة لتستمر الواجهة الأساسية عند انقطاع الاتصال. توجد طبقة طابور للمسودات المسموح بها، بينما تبقى الاعتمادات والمدفوعات والأرصدة والتحويلات والتسويات والصلاحيات وكلمات المرور عمليات متصلة بالإنترنت لتجنب الازدواج أو التعارض المالي.

## التشغيل المحلي

بعد تنزيل المستودع، يمكن تشغيل خادم ملفات ثابت من مجلد المشروع، ثم فتح `index.html` عبر الخادم وليس عبر `file://` حتى يعمل service worker. اضبط عنوان Supabase والمفتاح العام في `js/config.js` فقط، ثم طبق ملفات `supabase/migrations` بالترتيب على مشروع المصنع. لا تضع بيانات الدخول أو أي مفتاح خدمة في الملفات أو سجل Git.

## الترحيلات

تبدأ الترحيلات من `001_factory_v3.sql` ثم دوال المنتجات والمبيعات والمخزون والمالية والموظفين والعمليات والتوافق، وتستمر حتى ترحيلات حماية الدفع والإنتاج والمرتبات والصلاحيات ودورة حياة الموظف وإعدادات المصنع والتحويلات والجرد. يجب تطبيقها بالترتيب؛ وكل ترحيل موثق في اسمه ويعتمد على المخطط الفعلي الذي تم فحصه من Supabase.

## الاختبارات الحالية

يحتوي `docs/test-progress-v3.md` على سجل الاختبار المرحلي. شملت الاختبارات تحميل لوحة المدير، فتح وإغلاق النماذج الأساسية، المنتجات، نقطة البيع، المخزون، الموردين والمشتريات، المرتجعات، الإنتاج، الخزائن والبنوك، المصروفات، الموظفين، المرتبات، المستخدمين، الأدوار، التدقيق والإعدادات. لم تُنشأ سجلات إنتاج وهمية أثناء الاختبار البصري.

## النشر

قبل نشر النسخة النهائية يجب تشغيل فحص JavaScript و`git diff --check`، مراجعة عدم وجود أسرار، اختبار المقاسات الشائعة للهاتف والكمبيوتر، ثم الالتزام على فرع البناء ودفعه إلى GitHub. بعد مراجعة النسخة يجب دمجها في الفرع المنشور ومراقبة GitHub Pages والتحقق من الرابط العام.
